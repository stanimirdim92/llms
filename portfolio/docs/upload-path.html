The upload path, file by file

What actually runs between a client sending bytes and those bytes becoming answerable. Traced from source at commit 6f9e3ab — not from the README, which describes the shape rather than the order.

Two doors: HTTP + worker, or Streamlit in-process Three processes Two atomic boundaries

Door A — the HTTP path

This is the production path. It ends at 202 before any parsing happens, so the request is short and the expensive work belongs to a different process.

00
app/api/main.py boot, once

The lifespan runs before the first request: require_provider_credentials() and require_reranker_backend() abort the process when a key is missing, then init_db() takes a Postgres advisory lock, runs alembic upgrade head and installs procrastinate's schema. Routers mount with /v1 prefixes; health mounts unprefixed and unauthenticated.

guards A container with no Anthropic or Voyage key would otherwise start, pass its health check, accept uploads, and fail every one of them individually.
01
app/api/deps.py api

Three dependencies resolve before the handler body runs. CurrentTenant reads the x-api-key header, resolves it through auth/service.py::resolve_principal, and 401s on anything wrong with one message for every failure mode. require_scopes(DOCUMENTS_WRITE) 403s and names the missing scope. rate_limited("upload", …) counts in Redis and fails open.

guards The returned tenant_id is the only input to retrieval scoping. Nothing from the body or query string may reach it — a client-chosen scope reads another tenant's documents. nginx has already applied a separate per-IP limit_req at the edge, keyed differently on purpose.
02
app/ingestion/formats.py api

is_supported_upload(filename) checks the extension against a pinned allowlist. The whole file deliberately imports nothing from Docling; deriving the list from Docling's own mapping cost ~2s of startup and ~157MB of RSS per api process. A test compares the pinned list against Docling's real mapping in CI, where importing it is free.

guards Both the accidental cost and the quiet risk: a derived list means a routine dependency bump widens what a public endpoint accepts.
03
app/ingestion/uploads.py api

Bytes are read into memory, size-checked against MAX_UPLOAD_SIZE_MB (413), then four pure helpers give the document its identity:

  • upload_doc_id — f"{tenant_id}-{sha256(tenant_id + NUL + bytes)[:32]}". Deterministic, so re-uploading identical content is an update; tenant-salted, so two tenants never share a row or a point set, and comparing ids cannot reveal they uploaded the same file.
  • content_digest — plain sha256(bytes)[:16], no salt. Answers the one question the id cannot: did the bytes change while the id stayed the same?
  • safe_filename — Path(name).name, rejecting empty and hidden names, because a client-supplied ../../evil.py is an arbitrary file write.
  • document_upload_path — <root>/<tenant>/<doc_id>/<file>, containment-checked at both levels.
guards doc_id is in the path because a filename is not an identity. Without it, two documents named report.pdf share a path, worker A reads B's bytes, and B's content is filed under A's id with B's hash recorded as A's — so nothing afterwards looks wrong. The damage is sticky, because the parse cache is keyed by doc_id too.
04
uploads.py::write_upload api → thread

Called through asyncio.to_thread, because it blocks. It writes .<name>.partial and then os.replaces it into position.

guards The rename is the point. A direct write is visible to the worker from the first block, so a worker that dequeues mid-write parses a truncated document and records the truncation as the document.
05
app/api/routers/documents.py api

One session, two writes, one commit. stage_document_record upserts the row at status pending and deliberately does not commit; defer_document_ingest inserts the queue job on the same raw psycopg connection; then session.commit().

guards The two failure windows this closes are both silent. Row committed and enqueue failed leaves a document in pending forever, indistinguishable from one still queued. Enqueue committed and row rolled back leaves a job whose document does not exist. This is the reason the queue is Postgres-backed at all.
06
app/worker/app.py api

The api reaches the queue through this module and never imports tasks.py. It defers by task name with allow_unknown=True, so the implementation — and Docling, and torch — stay in the worker image. expected_digest travels with the job.

guards Measured: the first upload spent ~10s importing Docling inside the request. The trade is that a wrong task name is no longer an import error but a job no worker claims, so one constant serves both sides and a test asserts they match.
07
app/api/schemas.py api

202 Accepted with {tenant_id, doc_id, status: "pending"}. GET /v1/documents/{doc_id} is how a client follows the rest, and its query carries tenant_id in the WHERE clause so another tenant's document is a 404 rather than a row.

Then the worker

08
app/worker/tasks.py worker

The registered task. init_db(), mark_document_processing, require_provider_credentials(), then ingest_document. On any exception it tries to write failed with the message and re-raises so procrastinate retries (3 attempts, exponential backoff).

guards Without the record, a failed ingest looks identical to a document never uploaded. Without the re-raise, procrastinate marks the job succeeded and never retries the transient cases. Two things it deliberately cannot fix: an unreachable Postgres (recording that needs the database) and cancellation, which is a BaseException and is left for a legitimate retry.
09
app/ingestion/pipeline.py worker → thread

_parse_and_chunk runs in a thread — it is CPU-bound, and marking it async def would free nothing. It reads the file once, and its first act is to compare content_digest(bytes) against expected_digest.

guards The hash happens before the parse, and the ordering is the whole guard: verifying afterwards detects the swap and leaves a poisoned cache under this doc_id, which every later re-ingest reads from.
10
app/ingestion/parser.py worker

Cache first: processed_dir/<doc_id>.json. On a miss, Docling converts with generate_picture_images=True and a 90s document_timeout, and the result is saved to that path.

guards Anything other than ConversionStatus.SUCCESS raises. Docling reports a timeout by returning — a warning, a TIMEOUT error item, PARTIAL_SUCCESS, and no further pages — and a truncated document is indistinguishable from a complete one here. Accepting it would persist the truncation permanently, since the next ingest loads the cache.
11
app/ingestion/figure_extractor.py worker · vision call

Every PictureItem is enumerated; images below figure_min_dimension_px are dropped while still consuming their index. Each surviving image is PNG-encoded once, written to <figure_id>-<sha256[:16]>.png, and captioned by one Anthropic vision call or from the caption-<sha256>.txt cache. Captions that read as refusals, or are too short, are dropped after the call.

guards A caption is a figure's only searchable text, so an unusable one is worse than no figure: a one-page CV produced five "figures" — all ~20×20px icons — whose captions were the model saying it could not see the image, and those refusals then won reranking. Both the caption and the image file are content-addressed, so a shifted index can never serve one figure's bytes under another's caption.
12
app/ingestion/chunker.py worker

HybridChunker over the parsed document, sized by a HuggingFace tokenizer at chunk_max_tokens. Three kinds come out: text chunks ({doc_id}-text-NNNN, blanks skipped), tables as one atomic markdown chunk each, and figures as their caption. Every chunk carries filename.

guards Tables are never split mid-row. filename is on every chunk because without it the only label is a 65-character doc_id — a question naming a file gets "I have no document by that name" alongside a summary of that exact document. Observed in production.
13
pipeline.py::ingest_document worker

No chunks means EmptyDocumentError, raised before anything is written. Otherwise a fresh ingestion_version = new_id() is minted here — not by either caller — so one ingest is one version whichever door it came through.

guards A scanned, image-only PDF parses fine and yields nothing: a real 2MB flyer extracted 30 characters. Recording that as ingested with chunk_count=0 is a lie the user can only find by asking a question and getting someone else's document.
14
app/vectorstore/qdrant_store.py worker → thread

upsert(chunks, ingestion_version) refuses a batch spanning two documents or two tenants, then writes each chunk with a point id of uuid5(ns, f"{version}:{chunk_id}") and a payload stamped with the version, tenant, doc, chunk id and filename. Embeddings come from app/embeddings/voyage.py, one call per batch.

guards It deletes nothing. The version in the point id is what keeps this generation from colliding with the previous one, so the insert is not destructive and there is something to fall back to. Nothing here is readable yet — the version is not the active one.
15
app/registry/db.py worker

activate_document_version — one UPDATE, with tenant_id in the WHERE clause, setting the version, the chunk count, status ingested, and clearing any previous error. It raises DocumentNotFoundError when rowcount == 0.

guards This is the commit point: one statement, so a concurrent reader sees the old version or the new one and never a document searchable at no version. It raises where mark_document_* stay silent, because silence here leaves a generation that is inserted, invisible, and uncollectable.
16
qdrant_store.delete_superseded worker · best effort

After the flip, every generation of this document except the live one is deleted. Wrapped in try/except: a failure logs ingestion.prune_failed and the ingest still succeeds.

guards Two ways to get this wrong. Pruning before the flip would delete the generation still serving reads. Letting it raise would turn a published, working document into a reported failure.

Door B — Streamlit

B
streamlit_app/Home.py streamlit

This UI calls the pipeline in process, so no FastAPI dependency runs for it. It asks for an API key and resolves it through the same auth.service.resolve_tenant the dependency uses, builds its path with the same document_upload_path and write_upload, stages the pending row itself, and then calls ingest_document synchronously — bypassing the queue but not the registry.

guards It must never mint its own tenant id; that is exactly the client-chooses-its-own-scope hole the API closed. And it previously built <tenant>/<filename> — its own copy of the path-collision bug — which is why those helpers live in a shared module rather than in the router.

Where it becomes answerable. app/retrieval/retriever.py reads list_active_versions for the tenant and passes both the permitted doc_ids and their live versions into _build_filter. Postgres decides what is searchable; Qdrant cannot.

So the answer to "why isn't my document showing up" is almost always a row: status pending means the worker has not claimed it, processing means it is mid-parse, and ingested with a null version is the one state that should be impossible.
