## T002: Seed script ingests the pinned corpus into a dedicated tenant

**Requirements:** REQ-001, REQ-002 (`docs/EPIC_2_PLAN.md` §2.1 ¶1)

**Description:** `scripts/seed_eval_corpus.py`, mirroring `scripts/create_tenant.py`'s CLI
shape, creates one dedicated eval tenant and ingests T001's pinned documents through the
real pipeline with pinned chunker settings, so chunk ids in the golden set stay stable
across re-runs.

**Acceptance criteria:**
- [ ] `scripts/seed_eval_corpus.py` creates (or reuses, idempotently) one named tenant
      via `scripts/create_tenant.py`'s existing tenant-creation path — no duplicate
      tenant on a second run
- [ ] Ingests every T001 document via `app.ingestion.pipeline`, with `chunk_max_tokens`
      and any other chunker-affecting settings pinned to explicit values in the script
      (not read from ambient `Settings` defaults that could change later)
- [ ] Running the script twice against a clean-but-already-seeded tenant produces
      byte-identical `chunk_id` sets both times (idempotency), verified by the test below
- [ ] `argparse`-based CLI, lazy `init_db()` only after arg validation (per
      `scripts/create_tenant.py:164-168`), `asyncio.run(main())` entrypoint
- [ ] Documented as a one-time manual step requiring real `ANTHROPIC_API_KEY`/
      `VOYAGE_API_KEY` — not part of any CI job (`docs/MEMORY.md` gets a standing-directive

## T003: Hand-write and commit the golden Q&A set

**Requirements:** REQ-003, REQ-004, REQ-005 (`docs/EPIC_2_PLAN.md` §2.1 ¶2-4)

**Description:** 50+ grounded Q&A pairs against the T002 corpus, hand-written per
the `qdrant:qdrant-search-quality` plugin skill's golden-set methodology — not machine-generated
wholesale, since a set generated by the same model family that answers questions measures
self-consistency, not correctness.

**Acceptance criteria:**
- [ ] `data/eval/qa_dataset.jsonl` committed with 50+ rows, each carrying exactly:
      `question`, `answer`, `chunk_ids` (list, the golden retrieval set), `intent_label`
      (one of `metadata`/`factual`/`aggregate`/`out_of_scope` — `app/generation/intent_router.py:27`)
- [ ] Includes hand-written hard cases covering all of: a table-lookup question, a
      figure-grounded question, a question whose answer spans two documents, and a
      question the corpus genuinely cannot answer (correct `answer` is a stated refusal)
- [ ] No row was generated by prompting the same model family (Claude) to produce both
      question and answer from the corpus with no human review — each pair is
      human-authored or human-verified against the actual ingested chunks
- [ ] Every `chunk_ids` entry verified to exist in Qdrant for the seed tenant (same check
      as the T002 test, re-run here against the finished dataset)

**Verification:**
- [ ] Tests pass: `uv run pytest tests/unit/test_eval_golden_set.py -v`
- [ ] Manual check: hard-case category checklist above, reviewed before commit
